# Security Policy

## Supported versions

Security fixes are applied to the latest tagged release. Reports affecting the `main` branch are also accepted while the next release is being prepared. Older releases are handled on a best-effort basis according to severity and upgrade impact.

## Report a vulnerability privately

Do not open a public GitHub issue for a suspected vulnerability.

Use the [Haroone Agency contact form](https://haroone.com/contact) and include **Security report: Admin Reindex** in the subject or first line. Please provide:

- the affected module and Magento versions;
- the relevant configuration and queue backend, without credentials;
- clear reproduction steps and the expected security impact;
- the smallest useful log or request excerpt, with customer and store data removed;
- whether the issue is already public or known to another party.

Do not send passwords, API keys, authentication cookies, private keys, database exports, customer information, or production backups. If sensitive evidence is necessary, first request a secure exchange method through the contact form.

## Disclosure

Haroone Agency will validate the report, coordinate a fix and release where required, and credit the reporter when requested and appropriate. Please allow time for a patched release before publishing technical details.
